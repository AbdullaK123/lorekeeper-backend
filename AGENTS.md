# Repository Instructions

## Project management tracking

Before every final response, update the project management docs for that turn.
This applies to implementation, reviews, planning, testing, and teaching.

- `docs/current_sprint.md`: Record work, decisions, checks, and remaining work for the turn.
- `docs/project_plan.md`: Keep delivery status, priorities, and next steps current.
- `docs/design.md`: Keep design decisions, implementation status, and known limits current.
- `docs/user_stories.md`: Keep story coverage and acceptance status current.

Check all four docs each turn. Record unchanged scope when no delivery status changes.
Do not invent progress or repeat historical entries just to change a file.
State when no code changes or tests occur. Do not mark unverified work complete.
Backend routes and development tools alone do not complete product epics.
Update `docs/product_soul.md` when the audience, purpose, or product scope changes.
